# Luna Spa — دليل التشغيل (لوحة تحكم + قاعدة بيانات حقيقية)

تمت إضافة قاعدة بيانات حقيقية (Supabase) ولوحة تحكم كاملة للموقع **دون تغيير التصميم أو المحتوى الحالي**.
الموقع نفسه (index.html، services.html...) لم يتغيّر شكلاً — فقط أصبح يقرأ الخدمات والعروض والصور من قاعدة البيانات بدل أن تكون مكتوبة داخل الكود.

## لماذا Supabase؟
هو الخيار الأبسط من بين الحلول التي طلبتِها (Supabase / Firebase / Node+SQL): يعطيكِ **قاعدة بيانات PostgreSQL حقيقية + نظام تسجيل دخول + تخزين صور**، بدون الحاجة لتشغيل أو استضافة سيرفر Node بنفسك. حسابه المجاني كافٍ تماماً لصالون مثل Luna Spa.

## هيكل المشروع
```
luna-spa/
├── index.html, services.html, offers.html, gallery.html, booking.html, contact.html   ← الموقع (كما هو، بدون تغيير بالتصميم)
├── css/style.css
├── js/
│   ├── supabase-client.js   ← بيانات الاتصال بقاعدة البيانات (تعدّلينها مرة واحدة)
│   ├── data.js               ← دوال جلب البيانات من قاعدة البيانات
│   └── main.js                ← منطق الموقع (تم تحديثه ليقرأ من قاعدة البيانات)
├── database/
│   └── schema.sql            ← ملف SQL واحد ينشئ كل الجداول والصلاحيات ويزرع بياناتكِ الحالية
└── admin/                    ← لوحة تحكم Luna Spa (منفصلة عن موقع الزوار)
    ├── login.html             ← صفحة تسجيل الدخول
    ├── dashboard.html         ← لوحة التحكم (خدمات، عروض، معرض، حجوزات، رسائل، إعدادات)
    ├── css/admin.css
    └── js/{supabase-client.js, app.js}
```

## لوحة التحكم تدير الآن

- **الخدمات**: إضافة / تعديل / حذف، تغيير السعر، تغيير الصورة، تعديل الوصف، تفعيل/تعطيل الظهور في الموقع.
- **العروض**: إضافة / تعديل / حذف، الخدمات المشمولة، السعر القديم والجديد، تفعيل/تعطيل.
- **معرض الأعمال**: رفع / حذف صور مع تصنيفها.
- **الحجوزات**: عرض كل حجز (اسم، جوال، خدمة، تاريخ، وقت، ملاحظات) وتغيير حالته.
- **رسائل التواصل**: كل رسالة تُرسل من صفحة "تواصل معنا" تُحفظ وتظهر هنا، مع إمكانية تحديدها كمقروءة أو حذفها.
- **إعدادات النشاط**: الاسم، الجوال، واتساب، الموقع، TikTok/Instagram، الوصف، الشعار.

كل هذا **بدون فتح أي ملف كود** — فقط من واجهة لوحة التحكم.

## 1) إنشاء مشروع Supabase (5 دقائق)

1. اذهبي إلى https://supabase.com وأنشئي حساباً مجانياً.
2. اضغطي **New Project** → اختاري اسماً (مثلاً `luna-spa`) وكلمة مرور لقاعدة البيانات واحفظيها.
3. انتظري دقيقة حتى يجهز المشروع.

## 2) تشغيل قاعدة البيانات

1. من القائمة الجانبية اذهبي إلى **SQL Editor** → **New query**.
2. افتحي ملف `database/schema.sql` من هذا المشروع، انسخي **كل محتواه**، الصقيه في المحرر، واضغطي **Run**.
3. هذا الملف سينشئ كل الجداول (الخدمات، العروض، الصور، الحجوزات، **رسائل التواصل**، الإعدادات، المشرفين)، صلاحيات الوصول (RLS)، مخزن الصور (Storage bucket)، **ويزرع نفس الخدمات والعروض والصور الموجودة حالياً في موقعك** — بحيث لا يتغيّر شيء أمام الزوار في اليوم الأول.

> **ملاحظة:** إذا كنتِ قد شغّلتِ نسخة سابقة من `schema.sql` من قبل (بدون جدول رسائل التواصل)، **لا تعيدي تشغيل الملف كاملاً** — بدلاً من ذلك شغّلي فقط `database/add_contact_messages.sql`، وهو يضيف جدول الرسائل الجديد دون المساس بأي بيانات موجودة.

## 3) ربط الموقع بقاعدة البيانات

1. من Supabase: **Project Settings → API**.
2. انسخي القيمتين: **Project URL** و **anon public key**.
3. افتحي `js/supabase-client.js` (في مجلد الموقع) و`admin/js/supabase-client.js` (في لوحة التحكم) — **كلا الملفين** — والصقي القيمتين مكان:
   ```js
   const SUPABASE_URL = "https://YOUR-PROJECT-ID.supabase.co";
   const SUPABASE_ANON_KEY = "YOUR-ANON-PUBLIC-KEY";
   ```
   هذا المفتاح آمن للاستخدام في كود الموقع — لا يستطيع فعل أي شيء غير مسموح به بصلاحيات RLS المحددة في `schema.sql`.

## 4) إنشاء حساب المشرفة (صاحبة الصالون) — البريد وكلمة المرور

هذه هي بيانات الدخول الفعلية للوحة التحكم — أنتِ من تختارينها، وليست مكتوبة في أي مكان بالكود:

1. من Supabase: **Authentication → Users → Add user → Create new user**.
2. أدخلي:
   - **Email**: بريد صاحبة الصالون الحقيقي (مثال: `owner@lunaspa.sa`، أو أي بريد تفضلينه).
   - **Password**: كلمة مرور قوية من اختيارك (8 أحرف على الأقل، يُفضّل مزيج حروف وأرقام ورموز).
   - فعّلي خيار **"Auto Confirm User"** حتى يعمل الحساب فوراً دون الحاجة لتأكيد عبر إيميل.
3. اضغطي **Create user**. بعد إنشائه، انسخي الـ **User UID** الخاص به (يظهر بجانب اسمه في نفس الصفحة).
4. ارجعي إلى **SQL Editor** ونفّذي (استبدلي القيمتين بين علامتي الاقتباس ببريدك و UID الفعليين):
   ```sql
   insert into admins (user_id, email)
   values ('USER-UID-هنا', 'owner@lunaspa.sa');
   ```
   هذا هو ما يمنح هذا الحساب تحديداً صلاحية الدخول إلى لوحة التحكم — أي حساب آخر يسجّل دخول عادي لن يستطيع الوصول إليها حتى لو عرف كلمة المرور، لأن سياسات RLS تتحقق من وجوده في جدول `admins` تحديداً، وليس فقط من نجاح تسجيل الدخول.

هذا البريد وكلمة المرور هما بالضبط ما تُدخلينه لاحقاً في `admin/login.html`. لا يوجد بريد أو كلمة مرور افتراضية مكتوبة داخل المشروع — الحقل الظاهر في الصفحة (`admin@example.com`) مجرد نص توضيحي (placeholder) يختفي عند الكتابة، وليس بيانات دخول حقيقية.

## 5) تشغيل الموقع محلياً في VS Code

المشروع لا يحتاج أي تثبيت (لا npm، لا build step) — لكن **لا تفتحي ملف index.html مباشرة بالنقر عليه مرتين**، لأن طلبات قاعدة البيانات لا تعمل بهذه الطريقة (بروتوكول `file://`). افتحيه عبر سيرفر محلي بسيط:

**الطريقة الأسهل — إضافة Live Server:**
1. في VS Code، افتحي تبويب الإضافات (Extensions، أو `Ctrl+Shift+X`).
2. ابحثي عن **Live Server** (من Ritwick Dey) وثبّتيها.
3. افتحي مجلد المشروع كاملاً في VS Code: **File → Open Folder** واختاري مجلد `luna-spa`.
4. من مستكشف الملفات، افتحي `index.html`، ثم اضغطي **Go Live** في أسفل يمين الشاشة (أو زر يمين الفأرة على الملف → **Open with Live Server**).
5. سيفتح المتصفح تلقائياً على شيء مثل `http://127.0.0.1:5500/index.html`.
6. للوصول للوحة التحكم افتحي: `http://127.0.0.1:5500/admin/login.html`

**أو عبر Terminal المدمج في VS Code (بدون إضافات):**
1. **Terminal → New Terminal** داخل VS Code.
2. تأكدي أنكِ داخل مجلد المشروع (`cd luna-spa` إذا لزم).
3. شغّلي:
   ```bash
   python3 -m http.server 8080
   ```
   (على ويندوز قد يكون الأمر `python -m http.server 8080`)
4. افتحي في المتصفح:
   - الموقع: `http://localhost:8080/index.html`
   - لوحة التحكم: `http://localhost:8080/admin/login.html`
5. لإيقاف السيرفر: `Ctrl+C` داخل الـ Terminal.

> تذكّري: بدون إكمال الخطوات 1–3 (إنشاء مشروع Supabase، تشغيل `schema.sql`، ولصق المفاتيح في ملفي `supabase-client.js`) سيبقى الموقع عالقاً على "جاري التحميل..." — هذا متوقع ولا يعني وجود خطأ في الكود.

## 6) النشر (Deploy) على الإنترنت

الأبسط: **Netlify** أو **Vercel** أو **Cloudflare Pages** (جميعها مجانية لموقع كهذا):

1. ارفعي مجلد `luna-spa` بالكامل (بما فيه `admin/`) إلى مستودع GitHub، أو اسحبي المجلد مباشرة في Netlify Drop (https://app.netlify.com/drop) بدون Git حتى.
2. لا حاجة لأي إعدادات بناء (Build command) — فقط "Static site"، والمجلد الجذر هو `luna-spa`.
3. بعد النشر:
   - الموقع سيكون على: `https://your-site.netlify.app/`
   - لوحة التحكم على: `https://your-site.netlify.app/admin/login.html`

> يمكنك أيضاً نشر مجلد `admin/` على نطاق فرعي منفصل (مثل `admin.lunaspa.sa`) إن رغبتِ بفصله تماماً عن موقع الزوار — الكود لا يتطلب أي تغيير لذلك.

## 7) الدخول إلى لوحة التحكم

1. افتحي `admin/login.html`.
2. سجّلي الدخول بالبريد وكلمة المرور اللذين أنشأتِهما في الخطوة 4 — وليس بأي بيانات أخرى.
3. من اللوحة يمكنكِ إدارة كل شيء عبر الأزرار والتبويبات الجانبية (الخدمات، العروض، معرض الأعمال، الحجوزات، رسائل التواصل، إعدادات النشاط) — راجعي قسم "لوحة التحكم تدير الآن" أعلاه لتفاصيل كل تبويب.
4. للخروج: زر **تسجيل الخروج** أسفل القائمة الجانبية.

**أي تغيير تحفظينه من اللوحة يظهر فوراً على الموقع** — مثلاً إذا غيّرتِ سعر "تنظيف بشرة" من 96 إلى 110 ريال، فسيظهر 110 مباشرة في صفحة الخدمات والصفحة الرئيسية دون لمس أي كود.

## ملاحظات أمنية مهمة

- **لا تشاركي أبداً** أي مفتاح آخر غير الـ `anon public key` (تحديداً لا تستخدمي الـ `service_role key` في كود الموقع أو اللوحة — هذا المفتاح يتجاوز كل الحمايات ويجب أن يبقى سرياً في السيرفر فقط، وهذا المشروع لا يحتاجه إطلاقاً).
- **لا توجد أي كلمة مرور مكتوبة في الكود** — تسجيل الدخول يمر بالكامل عبر نظام مصادقة Supabase الحقيقي (Supabase Auth)، وكلمة المرور نفسها لا تُخزَّن ولا تُعرض في أي ملف من ملفات المشروع (لا في `login.html` ولا غيره) — Supabase يتحقق منها على خوادمه فقط.
- الزوار العاديون لا يستطيعون: تعديل الأسعار، حذف الصور، قراءة حجوزات أو رسائل عميلات أخريات — هذا مفروض من قاعدة البيانات نفسها (Row Level Security) وليس فقط من واجهة الموقع، فحتى لو حاول أحدهم التلاعب بالكود من المتصفح لن يستطيع الكتابة على البيانات أو قراءة ما لا يُسمح له بقراءته.
- لإضافة مشرفة أخرى مستقبلاً: كرري الخطوة 4 (إنشاء مستخدم + إضافته لجدول `admins`).
- لإلغاء صلاحية مشرفة: احذفي صفّها من جدول `admins` في Supabase (Table Editor) — حسابها سيبقى موجوداً لكنه لن يستطيع الدخول للوحة بعد الآن.

## استكشاف الأخطاء

| المشكلة | السبب المحتمل |
|---|---|
| الموقع يظهر "جاري التحميل..." باستمرار | لم يتم تعديل `SUPABASE_URL`/`SUPABASE_ANON_KEY` في `js/supabase-client.js` |
| لوحة التحكم تعيدكِ لصفحة الدخول فوراً | الحساب لم يُضَف إلى جدول `admins` (الخطوة 4)، أو `admin/js/supabase-client.js` لا يحمل نفس مفاتيح `js/supabase-client.js` |
| "بيانات الدخول غير صحيحة" رغم صحتها | تأكدي من تفعيل "Auto Confirm User" عند إنشاء الحساب، أو أكّدي البريد من رابط التأكيد الذي أرسلته Supabase |
| فشل رفع الصور | تأكدي من تنفيذ `schema.sql` كاملاً (ينشئ bucket باسم `luna-spa` وصلاحياته) |
| الحجوزات أو الرسائل لا تظهر في اللوحة | تأكدي أن `admin/js/supabase-client.js` يحمل نفس بيانات الاتصال، وأن الحساب مُدرج في جدول `admins` |
| رسائل "تواصل معنا" لا تُحفظ | إذا كانت قاعدة بياناتك من نسخة سابقة، شغّلي `database/add_contact_messages.sql` لإضافة الجدول الناقص |
| فتح الملف مباشرة (نقر مزدوج) لا يعمل | افتحي المشروع عبر Live Server أو `python3 -m http.server` كما في الخطوة 5 — لا تفتحي الملف بمسار `file://` |

## ما تم اختباره فعلياً

قبل التسليم، تم تشغيل كل صفحات الموقع ولوحة التحكم في متصفح آلي (headless browser) مع محاكاة كاملة لواجهة Supabase، والتحقق من:
- تحميل الصفحات الست للموقع بدون أخطاء برمجية
- عمل فلاتر الخدمات ومعرض الأعمال، وفتح الـ lightbox عند الضغط على صورة (تم اكتشاف وإصلاح خلل كانت طبقة شفافة فوق الصور تمنع فتحه)
- إرسال نموذج الحجز (حفظ في قاعدة البيانات + فتح واتساب)
- إرسال نموذج "تواصل معنا" (حفظ في قاعدة البيانات + فتح واتساب)
- تسجيل الدخول الخاطئ (يظهر رسالة خطأ) والصحيح (يوجّه للوحة التحكم)
- إضافة/تعديل/حذف خدمة، إضافة عرض، عرض الحجوزات وتغيير حالتها، عرض الرسائل وتحديدها كمقروءة، تحميل وحفظ الإعدادات
- تسجيل الخروج (يعيد لصفحة الدخول)

هذا لا يغني عن تجربة حقيقية بحساب Supabase فعلي بعد ربط المفاتيح، لكنه يؤكد أن منطق الكود نفسه سليم وخالٍ من الأخطاء البرمجية.
